# 앞으로 쓰는 글 — 한글 AI 티 규칙

**새 URL은 기본 금지.** 먼저 `bcstarts-ops`의 유지/수정/통합/삭제를 따른다. 검색 의도가 겹치면 합치는 쪽을 먼저 제안한다.


`https://bcstarts.org` 신규 글·칼럼에만 적용한다. 이미 올린 글은 사용자가 명시하기 전에는 다시 윤문하지 않는다.

출처: [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai) 분류 체계를 **규칙만** 가져온 것. 스킬 파이프라인·일괄 재작성은 쓰지 않는다.

## 언제 이 스킬을 연다

- 사용자가 신규 글, 칼럼, 품목 노트를 달라고 할 때
- 초안을 `data/posts.js` / `data/columns.js`에 넣을 때
- 배포 전 새 본문을 한 번 더 다듬을 때

## 4대 철칙

1. **의미 불변** — 사실, 주장, 수치, 날짜, 고유명사는 그대로.
2. **수술만** — AI 티가 난 구절만 고친다. 멀쩡한 문장은 손대지 않는다.
3. **장르 유지** — 칼럼은 칼럼, 품목 노트는 품목 노트. 문학·에세이 톤으로 옮기지 않는다.
4. **과윤문 금지** — 문장 절반 이상을 바꾸지 않는다. 숫자·실험 조건을 윤문 핑계로 고치지 않는다.

## 절대 건드리지 말 것

- 온도, 분, %, g, 차수, 발행일·실험일
- 사람 이름, 학원·시험·사이트 고유명사
- 큰따옴표 안 직접 인용, 메모 원문
- 공식 공고·면책·의료 비조언 고지

## 이 사이트 목소리

- 종결: **합쇼체** (`~습니다` / `~했습니다`)로 한 글을 일관. 해라체·해요체를 섞지 않는다.
- 1인칭 경험: `저는`, `제 기준`, `그날 메모`.
- 연도·장소를 박는다 (2024, 2025, 학원, 집).
- 완성 그램 레시피 금지. 실패 지점·변수 하나·메모 형식.
- 애드센스·검색 품질·심사 같은 메타 발언 본문 금지.

## 반드시 제거 (S1)

한 번만 나와도 뺀다.

| 패턴 | 대신 |
|------|------|
| `~에 대해(서)` 남발 | `~를` / `~은` |
| `~에 있어(서)` | `~에서` / `~을 볼 때` |
| `~되어진다` 이중 피동 | `~된다` / 능동 |
| `그/그녀` 강박 | 이름·역할, 또는 생략 |
| `결론적으로`, `시사하는 바가 크다`, `주목할 만하다` | 삭제하거나 구체 사실 |
| `혁신적인`, `새로운 패러다임` | 삭제 |
| `첫째·둘째·셋째`로 본문 뼈대 | 날짜·공정 이름·실제 순서 |
| 연결어미 뒤 습관적 쉼표 (`했고, 그래서`) | 필요한 쉼표만 |

## 밀도 보고 줄인다 (S2)

글 안에서 3회 이상이면 줄인다.

- `~를 통해`, `~와 관련하여`, `~에 기반하여`, `~라는 점에서`
- 문두 `또한 / 따라서 / 즉 / 나아가 / 아울러 / 게다가`
- `이는 ~을 의미한다`, `이 관점에서 보면`
- `것이다`, `~할 필요가 있다`, `~인 점`
- `~할 수 있을 것으로 보인다`, `~인 것으로 판단된다`
- `매우 / 정말` + 추상 수식 (`중요하고 핵심적인`)
- `~적 측면 / ~적 관점 / ~화` 남발
- 모든 문단이 3~4문장, 모든 문장이 비슷한 길이

## 리듬

- 단문과 복문을 섞는다. 강조는 짧은 문장.
- 종결을 `~습니다`만 네 번 연속하지 말고, `~습니다 / ~했습니다 / ~입니다`와 절 연결을 섞는다.
- 체크리스트·FAQ·핵심 요약을 글마다 같은 순서로 찍지 않는다. 칼럼은 관점+본문. 품목 노트는 실패 지점. 일지형이면 FAQ 생략.

## 작성 순서

1. 주제·장르·발행일을 정한다. 하루에 글 두 편을 올리지 않는다.
2. 초안은 경험·메모·숫자부터 쓴다. 개요 공식(`오늘은 ~에 대해`)으로 시작하지 않는다.
3. 위 S1/S2 표로 한 번 훑는다.
4. 배포 전 짧게 보고한다: 장르, 발행일, 건드린 문체 / 안 건드린 숫자.

기존 글 일괄 윤문, 스톡 사진 재삽입, 밤식빵 n차 양산은 하지 않는다.
